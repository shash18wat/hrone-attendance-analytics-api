# Starter code review

| # | Where | What is wrong | How to notice | How it is fixed |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It treats a naive timestamp as local wall time, so results depend on the machine time zone instead of IST. It also has no attendance-day input for an overnight shift. | Run the same 10:05 IST punch on a UTC and an IST host, or test a 05:00 punch for a 22:00-06:00 shift. | Convert instants to UTC, derive the IST attendance day, then compare against the shift start on that day. |
| 2 | `compute_late_minutes` | It does not truncate fractional seconds before applying the strict 10-minute grace boundary. | A punch at 09:40:00.900 should still be inside grace after R1 truncation. | Truncate input instants to whole seconds before calculating. |
| 3 | `compute_work_hours` | Python `round()` uses half-even rounding and floating-point arithmetic; the contract requires decimal half-up rounding. | Test a duration whose exact hour value is halfway between two hundredths. | Calculate with `Decimal` and `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | The shift end is always placed on the attendance date, so overnight shifts end a day too early. | Punch out at 06:40 for a 22:00-06:00 shift. | Put overnight shift end on the next calendar day. |
| 5 | `compute_overtime` | It compares an aware IST end with a potentially naive punch-out, which can raise `TypeError`; it also counts any positive overtime instead of requiring 30 minutes. | A 5-minute overtime case should produce 0, and a naive/aware comparison can be exercised directly. | Normalize instants to aware UTC and apply the 30-minute threshold before flooring minutes. |
| 6 | `health` | It returns 200 without checking MongoDB, so the runner can start tests while storage is unavailable. | Stop MongoDB and request `/health`; the starter still reports success. | Ping MongoDB and return 503 on a database error. |
| 7 | `create_employee` | The duplicate check followed by insert is racy; two concurrent requests can both pass the check. There is no unique database index. | Send parallel creates with the same `emp_code`. | Enforce uniqueness in MongoDB and translate `DuplicateKeyError` to 409. |
| 8 | `create_employee` | The body has no contract-level field/date/shift validation, and `shift_start == shift_end` is accepted. | Submit an invalid employee code, date, email, or equal shift times. | Add constrained Pydantic fields and date/shift validation. |
| 9 | `create_employee` | `created_at` is a naive local datetime, and the response returns a datetime instead of epoch milliseconds. | Inspect the response on a non-UTC host. | Store an aware UTC instant and serialize all API instants as epoch milliseconds. |
| 10 | `list_employees` | `skip = page * page_size` skips the first page and starts page 2 after another full page. | With 25 employees and page size 20, page 1 is empty. | Use `(page - 1) * page_size`. |
| 11 | `list_employees` | `total` ignores the department filter, and results are not sorted by `emp_code`. | Filter one department or request adjacent pages repeatedly. | Count the filtered query and sort by `emp_code` ascending. |
| 12 | `punch_in` | Unknown employees cause an unhandled subscript error. Timestamps use the host's local time, and invalid statuses or seconds-looking timestamps are accepted. | Punch in an unknown code, send `punched_at: 1783312500`, or use `ABSENT`. | Return 404 for unknown employees, validate epoch milliseconds/status, and convert through UTC/IST. |
| 13 | `punch_in` | Check-then-insert is not race-safe, and it does not truncate times or correctly derive overnight attendance dates. | Send simultaneous punches, or punch in before 06:00 for a 22:00-06:00 shift. | Derive the R1 date from the normalized instant and rely on a unique `(emp_code, date)` index. |
| 14 | `list_attendance` | It loads every matching document before sorting and slicing, which does not scale to 100,000 rows. | Profile a broad query on a large collection. | Use indexed MongoDB sorting, `skip`/`limit`, and a filtered `count_documents`. |
| 15 | `list_attendance` | Sorting omits the required `emp_code` tie-breaker, and the response invents an `id` field from MongoDB `_id`. Legacy `history` and `half_day` defaults are not filled. | Create same-date records and inspect the response shape for a legacy record. | Sort by date descending then code ascending, hide `_id`, and serialize the documented defaults. |
| 16 | Application setup | No indexes are created, leaving employee identity, punch-in uniqueness, list queries, and analytics unprotected or slow. | Inspect `getIndexes()` on a fresh database and run explain plans. | Create all named indexes idempotently at startup. |
| 17 | `compute_late_minutes` | The starter only reports late when the floored whole-minute value is greater than 10. That misses the required `09:40:01 -> 10` case for a 09:30 shift. | Test 09:40:00 and 09:40:01 against a 09:30 shift. | Compare exact elapsed seconds to 600, then floor elapsed minutes. |
| 18 | `list_employees`, `list_attendance` | Query parameters have no bounds or date validation; page 0/negative values, `page_size > 100`, malformed dates, and reversed date ranges can slip through. | Request page 0, page size 101, or `date_from` after `date_to`. | Constrain pagination, parse calendar dates, and reject reversed ranges with 422. |

I checked the default `load_dotenv()` behavior and kept it: it does not overwrite real environment variables, so injected `MONGO_URI` and `MONGO_DB` values take precedence. The starter's `compute_work_hours` formula was directionally right; its rounding method was the defect.
